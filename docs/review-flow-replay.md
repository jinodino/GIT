# 코드 리뷰 실행 흐름 재생

PR에서 AI 리뷰 워크플로가 실행되면 `review-flow.html`을 기록합니다. 리뷰가 성공적으로 끝나면 **Publish Review Flow** 워크플로가 이를 GitHub Pages의 첫 화면에 게시합니다. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정하세요. 게시된 주소는 `https://jinodino.github.io/GIT/`이며, 처음 게시가 끝난 뒤 Pages 설정이나 Publish Review Flow 실행 기록에서도 확인할 수 있습니다. 화면을 새로고침하면 가장 최근에 게시된 리뷰 기록이 보입니다. 재생은 자동으로 시작하며, 이전·다음 단계와 속도를 조절할 수 있습니다.

게시 워크플로는 같은 저장소에서 생성한 PR 중 기준 브랜치가 기본 브랜치인 실행만 처리합니다. 이전 기록은 웹에서 유지하지 않고, 새 리뷰가 성공적으로 게시될 때마다 첫 화면을 교체합니다. 실패한 실행이나 다른 브랜치를 대상으로 한 PR은 게시되지 않습니다. 원본 아티팩트는 Actions 실행 기록에서 7일간 내려받을 수 있습니다.

화면에는 PR 이벤트, 변경 파일 선별, 리뷰 프롬프트, LLM의 도구 호출, 도구 결과 요약, 리뷰 초안, 자기 비판, 수정된 리뷰, 최종 리뷰, PR 댓글과 수정 제안 게시 시도가 순서대로 표시됩니다. 각 단계에서 출발점과 도착점, 입력값, 처리 내용, 출력값을 볼 수 있습니다. 값은 해당 GitHub Actions 실행에서 수집한 것이며, HTML을 연 뒤 GitHub나 OpenAI에 다시 요청하지 않습니다.

도구 결과 원문 전체는 저장하지 않습니다. 파일 읽기는 줄 수와 문자 수, 코드 검색은 결과 개수와 위치, Ruff는 진단 개수와 코드를 기록합니다. 프롬프트·LLM의 리뷰 내용·자기 비판은 최대 2,400자까지 보관하고 흔한 API 토큰 형식은 가립니다. GitHub Pages 화면은 공개되므로 다른 저장소의 비공개 코드나 민감한 리뷰 기록을 이 방식으로 게시하지 마세요.

워크플로는 보안을 위해 PR의 **base 커밋에서 에이전트 코드를 설치**합니다. 이 기능이 들어 있는 PR을 열었을 때는 아직 base에 재생 코드가 없으므로 그 PR 실행에서 아티팩트가 생성되지 않습니다. 기능을 base 브랜치에 반영한 뒤 새 PR을 열거나 기존 PR에 새 커밋을 push하면 재생 기록이 생성됩니다.
